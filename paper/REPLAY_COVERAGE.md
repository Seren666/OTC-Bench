# CPU replay coverage

Tested scoring environment: Python 3.11.15, NumPy 1.26.4, pandas 2.3.3. Model-generation environments are separately recorded in `configs/` and `paper/inference_configs/`; this is cached-answer scoring replay, not weight-level inference reproduction.

`python benchmark.py verify` verifies every packaged file SHA256. `python paper_replay.py --output replayed_paper` regenerates:

- W and frozen A labels/core decisions for all 38,400 original answers.
- Main four-condition rates, signed paired contrasts and target-cluster intervals; full five-label distributions and 5x5 transitions; target/donor gains, losses and net changes.
- Main Table 3 W control matches, joint target/pair denominators and donor counts; majority/unanimous readability subset endpoint counts.
- Per-donor target/donor counts and annotated-instance stratum contrasts/intervals.
- The E/W exact-vs-word response-format table.
- Matched 32/128-token answer/stop checks and full-cohort endpoint contrasts replacing only 140 length-stopped outputs; all 20 controls held unchanged.
- Pooled probability/challenge audit endpoint concordance, all 30 probability-audit paired-effect rows/intervals, and the selected 29-comparison author-coding/word-change cross-tab.

The command compares recomputed quantities to the released tables and fails on disagreement. Its report locks the package checksums and must be regenerated before publication if package files change. Initial individual rater forms, free-text reasons and adjudication history remain private, so their aggregate reliability table cannot be independently regenerated from public forms. Rendering photographic inputs requires separately obtaining the licensed source images; numerical replay does not download them. Not every auxiliary display or plot is generated by this one command: quantitative figures are supplied with their data map and hashes.
